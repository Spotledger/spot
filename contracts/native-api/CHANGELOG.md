# Native API contract changelog

Every change is an ADR plus a semantic version bump (blueprint §4, contracts-first rule). Additive changes bump the minor version and keep the `/api/v1` prefix; breaking changes need a new major version and prefix (see `openapi.yaml`, "Versioning").

## 0.26.0 (draft, awaiting architecture-owner approval)

Additive (WP-CON-03.T67; the architecture owner gave the lead authority over contract changes on 31 Oct 2026 and for 12 Nov 2026); `/api/v1` and every existing path, operation, property and error code are unchanged. 1 operation (192 in all, 189 without the health probes and the realtime upgrade) and 1 error code (149) are new. Tag `link`.
- **`link_inbound`** (`POST /api/v1/link/inbound/{peer}`, **no session**, `security: []`): the inbound webhook of an external peer (ADR-058 rule 12). The peer proves itself by `X-Spot-Signature: t=<unix>,v1=<hex hmac-sha256(secret, t + "." + body)>` (the outbound webhook scheme, one scheme) inside a 5 minute window, with a durable nonce claim against replay; source allow-list and a per-peer body cap. Order: rate limit (charged to the name in the path before the peer is looked up), allow-list, cap, signature and window, nonce claim, then the link grant. Answers `202 {"accepted": true}`.
- **One refusal:** every refusal except the rate limit is `401 link_inbound.unauthorized` (new code) with one status, one set of headers and the body `{"error": {"code": "link_inbound.unauthorized"}}`, no request id: an unknown peer, a bad or missing signature, a stale timestamp, a replay, a source outside the allow-list, a malformed peer name and a body over the cap (a `401`, deliberately never a `413`). A peer over its limit gets `429 api.rate_limited` with `Retry-After`.
- Peer names are `^[a-z0-9][a-z0-9_-]{0,63}$`; a peer id with `.` or `:` cannot be addressed.
- `check.py` rule 33 (table driven, `GROUP_PINS`) and `conformance.rs` (version, 189 non-health operations, 149 codes, a `pin_group` test); `registry.rs` carries the new code. The operation is not served as a registry group until the follow-up below.
- **Decisions taken here (open questions answered with the recommended option):** (1) **the path is under `/api/v1`**, not the `/link/inbound/{peer}` of the brief and of the route as first written, because rule 3 of `check.py` and the contract's prefix rule admit only `/api/v1/...` and `/api/health/...`; the external peer's configured URL is the new path. (2) **the 429 reuses `api.rate_limited`**: the registry already has the equivalent, so no `link_inbound.rate_limited` code is added. (3) `link_inbound.unauthorized` is new: the existing 401 codes (`auth.required`, `connector.signature_invalid`) name another mechanism and would tell a peer which route it hit.
- **Follow-up inside WP-CTL-11.T4's owned paths (not done here):** the route file `routes/link_inbound.rs` changes `PATH` to `/api/v1/link/inbound/{peer}`, answers `api.rate_limited` instead of `link_inbound.rate_limited` (code string, `Retry-After` header, and its tests), and gains `SERVES`, `required_ports`, `routes` and `PUBLIC`; the host mount through `SiteCtx::router_layer` is removed; `docs/running-spot/link_external.md` names the new URL.
- **compatibility.** A 0.25.1 client is unaffected: the operation is new. A peer reads the URL from its link configuration; a client reads `version` from `GET /api/health/live` (0.26.0 or later).

## 0.25.1 (draft, awaiting architecture-owner approval)

Fix (WP-IAM-12.T4 open question 1; the architecture owner gave the lead authority over contract changes on 31 Oct 2026 and for 12 Nov 2026); `/api/v1`, every path, operation and error code are unchanged (191 operations, 148 codes).

- two error codes: `print.format_unknown` (404, the DocType defines no print format with that name — a name belonging to another DocType answers the same) and `print.render_failed` (500, retryable false, and neither the message nor `details` carries template text or document content) — 61 codes in all. A site with no print service answers `service.not_configured` with status 501, as the other unconfigured optional services already do (it stays outside the registry, as it is for files);
- rate class `interactive`, the class `report_run` runs in (`report_list` and `report_describe` state it for their own operations); no new class;
- `check.py` rule 14 (with a self-test case per part): the operation is a read-only `GET` (no other method, no request body), its responses are `application/pdf` only, `format` is the only query parameter, and no response header or property names a path or a storage key. The `spot-http` conformance suite lists `print_get` in `NOT_YET_SERVED` until WP-PLT-13.T2 serves it, and the Rust registry gains the two codes;
- **compatibility.** A server that does not implement this operation answers `404` (unknown route) or `501` (no print service), so a client reads `Live.version` from `/api/health/live` first and treats printing as unavailable below `0.7.0`: it hides the print action and keeps every other operation, which are byte-for-byte the 0.6.0 ones. Nothing is removed, renamed or reshaped, so a 0.6.0 client talking to a 0.7.0 server is unaffected.
